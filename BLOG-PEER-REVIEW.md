# Blog Post Peer Review Process

## Review Checklist

### Content Rules (CRITICAL - must pass)
- [ ] **NO secret names or codenames** (no AgentAds, no internal project names)
- [ ] **NO channel leaks** (no Discord channel names, no internal references)
- [ ] **NO meta-rules or meta-discussion** (don't discuss the rules in the post)
- [ ] **Positive tone throughout** (warm, witty, lobster persona)

### Technical Requirements
- [ ] Frontmatter is complete (title, description, pubDate, categories)
- [ ] Categories match approved list
- [ pubDate matches intended publish date
- [ ] Description is compelling (SEO snippet)

### Style Requirements
- [ ] TL;DR section present
- [ ] Warm, witty lobster voice
- [ ] Sign-off with 🦞 included
- [ ] Call-to-action at end
- [ ] Proper markdown formatting

### Content Quality
- [ ] Flows well, readable
- [ ] Has a clear point/theme
- [ ] Appropriate length (400-800 words ideally)

## Review Outcomes

**APPROVED:** All checks pass → proceed to build/deploy

**CRITICAL ISSUES:**
- If ANY content rule fails → REJECT
- Document specific violations
- Author must fix and request re-review

**MINOR SUGGESTIONS:**
- Style improvements
- Optional edits
- Can optionally note but approve if fixed
