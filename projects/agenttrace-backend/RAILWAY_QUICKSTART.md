# AgentTrace Backend - Railway Quickstart

Deploy this FastAPI backend to Railway in under 5 minutes.

## Prerequisites

- Railway CLI installed: `npm install -g @railway/cli`
- Railway account: https://railway.app
- (Optional) Cloudflare R2 account for session storage

## Quick Deploy (One-Click)

### 1. Login to Railway

```bash
railway login
```

### 2. Create Project

```bash
railway init
# Choose: "Empty Project"
# Name it: "agenttrace-backend"
```

### 3. Add PostgreSQL Database

```bash
railway add
# Select: Postgres
```

### 4. Set Environment Variables

Either use the CLI or Railway dashboard.

**Via CLI:**
```bash
# Required - Generate a secret key
export SECRET_KEY=$(openssl rand -hex 32)

railway variables set \
  SECRET_KEY="$SECRET_KEY" \
  ENVIRONMENT="production" \
  DEBUG="false" \
  CORS_ORIGINS="https://yourdomain.com"
```

**Via Dashboard:**
1. Go to your project
2. Click "Variables" tab
3. Add each variable from `railway.env.example`

### 5. Deploy

```bash
railway up
```

That's it! Your app is live.

## Manual Deployment Steps

If the quick deploy doesn't work:

### Step 1: Create Project

```bash
railway login
railway init
# Select "Empty Project"
```

### Step 2: Provision Services

```bash
# Add PostgreSQL
railway add
# Select "Database" → "PostgreSQL"

# (Optional) Add Redis for caching
railway add
# Select "Database" → "Redis"
```

### Step 3: Configure Environment

Copy variables from `railway.env.example` to Railway:

**Critical variables:**
```
DATABASE_URL      ← Auto-generated by Railway Postgres
SECRET_KEY        ← openssl rand -hex 32
ENVIRONMENT=production
DEBUG=false
```

**R2 Storage (optional):**
```
R2_BUCKET_NAME=
R2_ACCESS_KEY_ID=
R2_SECRET_ACCESS_KEY=
R2_ENDPOINT_URL=
```

### Step 4: Deploy

```bash
# From project root
git add .
git commit -m "Initial Railway deployment"
git push railway main

# Or deploy directly
railway up
```

### Step 5: Verify

```bash
# Get deployment URL
railway domain

# Test health endpoint
curl https://your-app.up.railway.app/health
```

## Environment Variables Reference

| Variable | Required | Description |
|----------|----------|-------------|
| `DATABASE_URL` | ✅ Yes | Railway Postgres auto-generates this |
| `SECRET_KEY` | ✅ Yes | JWT signing key (generate with `openssl rand -hex 32`) |
| `ENVIRONMENT` | ⚠️ Recommended | Set to `production` |
| `DEBUG` | ⚠️ Recommended | `false` in production |
| `CORS_ORIGINS` | ⚠️ Recommended | Your frontend domain(s) |
| `R2_*` | ❌ Optional | Cloudflare R2 storage config |

## Database Migrations

Migrations run automatically on deploy via `Procfile`.

**Manual migration:**
```bash
cd projects/agenttrace-backend

# Create migration
alembic revision --autogenerate -m "Add users table"

# Run migrations
alembic upgrade head
```

## Storage Configuration

### Without R2 (Local Storage Only)
- Sessions stored in `/tmp/agenttrace/sessions/`
- Fine for development, not for production
- Data is ephemeral (lost on redeploy)

### With Cloudflare R2
1. Create R2 bucket at https://dash.cloudflare.com
2. Create API token with R2 permissions
3. Set `R2_*` environment variables
4. App automatically uses R2, with local fallback

## Troubleshooting

### Database connection fails
```bash
# Check DATABASE_URL
railway variables

# Should look like:
# postgresql+asyncpg://user:pass@host:5432/railway
```

### Migrations failing
```bash
# Run migrations manually
railway run alembic upgrade head
```

### Health check returns 503
- Check PostgreSQL is provisioned
- Verify DATABASE_URL is set
- Check logs: `railway logs`

### R2 not working
- Verify all R2_* variables are set
- Check bucket exists and is accessible
- App will fall back to local storage
